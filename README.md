# AI-Powered Demand Forecasting and Inventory Optimization System

A B.Tech CSE minor project: a web app that manages products, stock and sales, trains three machine-learning models on historical sales data, predicts product demand, and recommends how much to reorder.

## Features

- **Admin login** (single account, bcrypt password hashing, token-protected pages, logout)
- **Dashboard** with live numbers and 3 charts (sales overview, inventory distribution, actual vs predicted demand), plus recent products, low-stock alerts and recent predictions. Shows proper empty states when there is no data.
- **Products**: add, edit, delete, search, with validation (no negative price/stock)
- **Inventory**: add / reduce / set stock, status colours (green In Stock, yellow Low Stock, red Out of Stock), negative stock is blocked
- **Sales data**: record sales (reduces stock, overselling blocked), history, totals, chart
- **Dataset upload**: CSV upload, validation, preview, row/column/missing-value counts
- **ML training**: Linear Regression, Random Forest and XGBoost trained inside scikit-learn Pipelines, compared on MAE, MSE, RMSE and R², best model saved with Joblib
- **Demand prediction**: real model predictions (never random), saved to the database
- **Inventory optimization**: `Reorder = max(0, Predicted Demand + Safety Stock - Current Stock)`
- **Model performance page** and **CSV reports** (inventory, sales, prediction history)

## Installation (macOS)

You need **Python 3.10+** and **Node.js 18+**. Check with:

```bash
python3 --version
node --version
```

If missing, install with [Homebrew](https://brew.sh): `brew install python node`.

### 1. Backend setup

```bash
cd ai-demand-forecasting/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Create your settings file (from the project root) and set a secret:

```bash
cd ..
cp .env.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(32))"   # copy the output
```

Open `.env` and paste the output as `AUTH_SECRET=...`. Optionally also fill `ADMIN_USERNAME` and `ADMIN_PASSWORD`.

> If you use Homebrew Python and see "externally-managed-environment", that is why we use the virtual environment (`.venv`) above.

Create the admin account (skip this if you set ADMIN_USERNAME / ADMIN_PASSWORD, or if you prefer the first-time setup screen in the browser):

```bash
cd backend
python create_admin.py
```

### 2. Frontend setup

```bash
cd ../frontend
npm install
```

No frontend `.env` is needed locally: the dev server forwards `/api` requests to the backend on port 8000.

## Running locally

Open two Terminal windows.

**Terminal 1 (backend):**
```bash
cd ai-demand-forecasting/backend
source .venv/bin/activate
uvicorn main:app --reload --port 8000
```
API docs are at http://localhost:8000/docs

**Terminal 2 (frontend):**
```bash
cd ai-demand-forecasting/frontend
npm run dev
```
Open http://localhost:5173 and log in. If no admin exists yet, the login page shows a one-time "create admin" form.

## Dataset requirements

A CSV file with **exactly these column names** (extra columns are ignored):

| Column | Meaning |
|--------|---------|
| `Item_ID` | product identifier (text) |
| `Store_ID` | store identifier (text) |
| `Item_Base_Price` | base price |
| `Discount_Applied` | discount (e.g. percent) |
| `Store_Footfall` | number of visitors |
| `Is_Holiday` | 0 or 1 |
| `Past_Week_Sales` | units sold in the previous week |
| `Units_Sold` | **target**: units sold (what the model predicts) |

At least 30 usable rows are needed, and the upload limit is 10 MB.

No dataset yet? Use `sample_data/sample_dataset.csv` (1,500 rows). **It is synthetic**, created by `backend/generate_sample_data.py` so you can demo the app. Do not present it as real sales data. Use your own dataset (the one from your project report) for real results.

## How model training works

1. Duplicate rows are removed; non-numeric values in numeric columns become missing; rows without a target are dropped.
2. Data is split **80% train / 20% test** (random split, because the dataset has no date column).
3. Each model is a scikit-learn `Pipeline`: median imputing + scaling for numbers, one-hot encoding for `Item_ID`/`Store_ID`, then the model. Everything is fitted on the training split only (no data leakage), and the same pipeline is reused for predictions.
4. Models: Linear Regression, Random Forest (100 trees, depth 12), XGBoost (200 trees, depth 5).
5. The best model is selected by **3-fold cross-validated RMSE on the training split**, so the test set is not used to choose it. The MAE, MSE, RMSE and R² shown on the performance page are measured on the untouched test split.
6. The best pipeline is saved with Joblib; unseen Item/Store IDs at prediction time are handled safely.

Which model wins depends on the data. On the synthetic sample, Linear Regression wins because that data was generated with mostly linear relationships. On real data, tree models often do better.

## Deployment

### Frontend on Vercel

1. Push the project to GitHub.
2. In Vercel: **Add New Project**, import the repo, set **Root Directory** to `frontend`. Framework preset: Vite (build `npm run build`, output `dist`). `vercel.json` already makes page refreshes work.
3. Add environment variable `VITE_API_URL` = your backend URL (for example `https://demand-forecasting-api.onrender.com`, no trailing slash).
4. Deploy. Then put the Vercel URL into the backend's `CORS_ORIGINS`.

### Backend on Render

The backend uses SQLite, trained models and uploaded files, **all stored on disk**. A cloud server's default disk is temporary, so you must choose one of these:

**Option A: persistent disk (recommended, keeps data)**
- Use `render.yaml` (New > Blueprint) or create a Web Service by hand with Root Directory `backend`, Build `pip install -r requirements.txt`, Start `uvicorn main:app --host 0.0.0.0 --port $PORT`.
- Attach a **Disk** mounted at `/var/data`. Render offers persistent disks on paid instance types only (check Render's current pricing/docs).
- Environment variables: `AUTH_SECRET` (long random string), `DATABASE_PATH=/var/data/app.db`, `MODEL_DIR=/var/data/ml_models`, `UPLOAD_DIR=/var/data/uploads`, `CORS_ORIGINS=https://your-app.vercel.app`, and `ADMIN_USERNAME` / `ADMIN_PASSWORD` for the first admin.

**Option B: free demo hosting (temporary data)**
- Same service without a disk. Everything stored on disk (database, uploaded CSV, trained model) is **wiped whenever the service restarts or redeploys**, and free services also sleep when idle.
- It is fine for a short demo: keep `ADMIN_USERNAME` / `ADMIN_PASSWORD` set so the admin is recreated automatically, then after each restart re-add a few products, upload the sample CSV and click Train Model again (about a minute).
- Do not rely on this for data you want to keep.

Other hosts that offer persistent volumes (Railway, Fly.io, a small VPS) work too: run the same start command and point the three path variables at the mounted volume.

### Environment variables summary

| Variable | Where | Purpose |
|----------|-------|---------|
| `AUTH_SECRET` | backend | signs login tokens (required, 16+ chars) |
| `DATABASE_PATH` | backend | SQLite file location |
| `MODEL_DIR` | backend | where the trained model is saved |
| `UPLOAD_DIR` | backend | where the uploaded CSV is saved |
| `CORS_ORIGINS` | backend | allowed frontend URLs |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | backend (optional) | auto-create the admin if none exists |
| `VITE_API_URL` | frontend | backend URL |

Never commit your real `.env` file (it is in `.gitignore`).

## Troubleshooting

- **"Cannot reach the server"**: the backend is not running, or `VITE_API_URL` / `CORS_ORIGINS` is wrong.
- **"Server misconfigured: set AUTH_SECRET"**: add `AUTH_SECRET` to `.env` and restart the backend.
- **"Missing required columns"**: check the CSV header spelling against the table above.
- **"The model is not trained yet"**: go to Dataset Upload, upload a CSV and click Train Model.
- **Port already in use**: stop the old process or use `--port 8001` (and update the proxy in `frontend/vite.config.js`).

## Notes and limitations

- Single admin account only (by design for a minor project).
- Predicted demand is for the same period as `Units_Sold` in your dataset. Safety stock and current stock should use that same unit/period for the reorder formula to make sense.
- Deleting a product also deletes its sales records.
